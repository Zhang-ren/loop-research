工作流与 Codex 的关系

入口可用 CLI 或 Codex 的 $research-loop Skill。入口提交任务后，Python 控制器保管实验状态和证据，按阶段启动独立的 Codex 角色。各角色通过 JSON Schema 返回结构化结果，训练和打分由接入的实验执行器运行。

  1. 确认需求与基线
  2. 提出差异化假设
  3. 并行训练与评测
  4. 复核与收敛
  5. 冻结测试与归档

当验证指标停滞且还有预算时，控制器可以补充调研、调整方向、试探参数边界或组合已经测过的改进后重训。实际支持的动作取决于适配器和冻结协议。达标或预算耗尽后进入验收与归档。

控制器

LangGraph 表达工作阶段与条件路由。文件存储维护状态、租约、证据摘要和可重复触发的回执。

执行与核验

Codex 规划、编码、分析和复核从独立会话启动。候选工作区隔离，按冻结协议执行并保存真实测量。

项目经验

研究级项目 ID 限制经验检索。正式发布需要原件证据、独立复核及用户批准具体版本。

安装与首次运行

在 Linux x86_64、Python 3.12 上完成了迁移实测。安装 Git、uv 和 Codex CLI，使用现有 Codex 登录。隔离训练模式还需要主机允许 bubblewrap 建立所需命名空间。

uv sync --locked --no-editable
codex --version
codex login status

如需登录，运行 codex login。如果 CLI 路径未被自动发现，可设置 LOOP_CODEX_BINARY。

uv run --no-sync loop-research preflight examples/breast-cancer.json
uv run --no-sync loop-research init examples/breast-cancer.json runs/classifier
uv run --no-sync loop-research status runs/classifier

init 测量基线。下一条命令才开始模型规划和候选搜索，消耗 Codex 账户额度。模型可能选择不同的可验证假设。使用相同的代码、数据、参数与种子复跑某次测量。

uv run --no-sync loop-research run runs/classifier
uv run --no-sync loop-research budget runs/classifier
uv run --no-sync loop-research report runs/classifier
uv run --no-sync pytest -q
尝试用户自带脚本的合成传感器示例

复制示例到独立目录并提交输入。实验脚本只需要 Python 标准库。

EXAMPLE_ROOT="$(mktemp -d)"
cp -R examples/command-benchmark/. "$EXAMPLE_ROOT/"
git -C "$EXAMPLE_ROOT" init
git -C "$EXAMPLE_ROOT" add .
git -C "$EXAMPLE_ROOT" commit -m "Freeze synthetic benchmark"
uv run --no-sync loop-research init \
  "$EXAMPLE_ROOT/experiment.template.json" runs/sensor
uv run --no-sync loop-research run runs/sensor

Git 提交需要本机已配置提交身份。模板和脚本也可从仓库的 examples/command-benchmark 目录查看。

接入已有实验仓库

在 Codex 中用 $research-loop 指定项目目录、目标和研究预算，也可以手动调用 CLI。准备阶段检查环境和数据并给出补问，用户确认协议后再启动真实基线。

uv run --no-sync loop-research prepare-study /path/to/project runs/my-study \
  --objective "提高现有验证集的宏 F1" --non-interactive

优先复用项目的 experiment.json。如果返回 issues，可以补齐数据或依赖，或用 --answers /path/to/answers.json 为同一个运行目录补充答案。确认生成的说明、命令、切分和可修改范围后，加 --start 启动。仅测基线时使用 init RUN/study-spec.json RUN。

入口需要提供的信息
prepare-studyGit 提交、训练或评测命令、数据和固定划分、指标方向与阈值、预算及允许的参数。可声明实验解释器、依赖程序或 GPU。
study SPEC RUN现有的完整配置。初始化后同一研究继续使用相同配置和运行目录。
onboard PROJECT RUN可运行的本地原生 Python 仓库与目标。按需提供 Python 解释器、预处理产物和必须的数据文件。
Linux 原生仓库从发现推进到候选搜索 
uv run --no-sync loop-research onboard /path/to/project runs/native \
  --objective "保持原生评分，改善开发验证指标" \
  --execute --interpreter /path/to/experiment/python \
  --research --rounds 2 --candidates 6

只做发现时省略执行与搜索选项。存在预处理缓存时可通过 --artifacts 提供。候选启动前要求通过原生基线一致性、数据划分和评分器资格检查。失败时重跑同一入口并查看该目录的 status。如果已经进入候选周期，研究账本在运行目录的 study/ 下。

自定义脚本接口与可修改边界

命令适配用 LOOP_PARAMETERS、LOOP_SPLIT_MANIFEST、LOOP_SPLIT 和 LOOP_SEED 传入参数、划分和种子。评测脚本向 LOOP_METRICS 写出指标 JSON。普通命令模式面向受信脚本。隔离预测、逐折和原生模式另行分开训练输入、预测及评分。配合提交冻结文件和声明只读数据限制可变范围。查看仓库中的接入文档

监控、复核与恢复

任务CLI 命令
查看运行status RUN、budget RUN、report RUN。训练预算与角色调用分别统计。
手动或定时推进tick RUN、run RUN、serve RUN --interval-seconds 60。外部事件传 --event-id，重投使用相同 ID。
停止与对账stop RUN，可加 --cancel-training。用 reconcile RUN 查训练回执。
独立复核recheck-review RUN REVIEW_ID，或用 resolve-review RUN REVIEW_ID REVIEWER RATIONALE 留档决定。用 --accept 明确接受。
复跑或兼容恢复reproduce RUN EVIDENCE_ID 重跑已记录的测量。resume RUN --python /path/to/python 使用归档控制器恢复。
调整评价协议revise-metrics 或 revise-study 在新目录实测基线，保留与旧口径的关联。

从 RUN/state.json 看当前状态。jobs/ 和 evidence/ 保存训练与测量回执，workers/ 保存角色输入输出，memory/ 保存项目经验的草案和批准记录。对外分享前应按项目的数据授权处理这些文件。

人工审核、批准和回滚 Skill

更新草案需要单独批准。回滚恢复此前已批准的版本。入口 Skill 面向通用接入，研究总结产生的 Skill 则随原研究目录管理。

从公开选题生成论文草稿

试点脚本检索公开论文，固定上游版本，复跑示例，并将审查通过的候选结果写入论文草稿。以下手写数字试点需要实验解释器可导入 scikit-learn 和 Matplotlib，并能访问所需公开资源。重用同一运行目录可读取已完成阶段的回执。

uv run --no-sync python scripts/run_public_paper_study.py runs/digits-paper \
  --interpreter /path/to/experiment/python \
  --brief "复现公开的手写数字分类基线，比较三项单变量改动"

迁移与 GitHub 发布

新主机从源码和 uv.lock 重建环境，再重新登录 Codex 并配置实验自己的解释器与数据。已有研究的部分回执包含绝对路径，恢复时要重建原布局并验证归档。无法恢复原布局时，可在新目录重测基线。

发布仓库包含源代码、配置模板、合成数据、回归测试和第三方声明。原实验运行目录、模型权重、账户凭据和虚拟环境单独保存。

git status --short

从 ZIP 解压时先运行 git init -b main。公开源码前，由维护者决定是否为自有部分添加开源许可证。随包第三方文件附有各自的许可证和来源记录。

技术来源与验收范围

领域设计依据美团公开的 V1–V3 架构和 Karpathy AutoResearch。控制层采用 LangGraph、APScheduler 和本地文件账本，实验用 MLflow 记录。EvoScientist 提供随包的经验提案校验与发布模块，EvoSkills 提供研究方法和论文取用工具。PyAlex 接入 OpenAlex，DVC 与 Snakemake 为接入设计参考。

真实项目案例包括公开手写数字、MAPIE、Optuna、PyTorch 词级语言模型和 TabZilla。发布版本另含可独立运行的合成传感器例子。线上与云端能力属于范围外，长时间真实任务在途无人值守验收暂缓。
