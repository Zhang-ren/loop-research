# 架构与实现

## 从 V1 到本地 V3

| 设计来源 | 本仓库实现 |
| --- | --- |
| V1 实验循环 | 固定目标、业务知识、候选范围和验收条件。每个候选留下实际指标与源码差异，可据此选择或回退。 |
| V2 异步状态机 | 控制器将规划、派发、监控与归档拆开。短时 tick 单独推进状态，训练与控制器分离。调度器和手工入口遵守同一租约及回执。 |
| V3 图式搜索 | 规划、差异门禁、分离工作区、异步训练、全批汇总、独立复核及再规划。搜索沿候选证据、已知负例和方向池循环，收敛后运行独立冻结测试。 |

```text
用户 → CLI 或接入 Skill → Python 控制器 → 独立 Codex 角色
                               │
                               ├─ 研究目标、冻结协议和方向池
                               ├─ 候选执行器 → 训练、验证与最终冻结评测
                               └─ 回执和项目经验 → 状态、报告、复跑
```

运行入口可以嵌入日常 Codex 会话。控制器发起的新角色会话只完成指定任务，研究循环的推进权在控制器。默认每次模型调用单独启动进程并验证 JSON Schema。角色的模型、超时、回执和用量可追溯。模型生成的评分摘要不能代替评测器的结果。

## 模块与运行状态

| 模块 | 担当 |
| --- | --- |
| `cli.py`、`study_intake.py`、`preflight.py` | 公共 CLI，发现项目和确认协议，检查数据、入口及运行环境。 |
| `engine.py`、`models.py`、`storage.py` | 状态机、预算、硬门槛、路由和持久状态。LangGraph 每次选取一个控制节点执行，文件提交保存跨进程状态。 |
| `workers.py`、`literature.py`、`literature_backend.py` | Codex 角色进程、结构化结果、来源卡片、外部匹配与原文引用校验。 |
| `onboard_native.py`、`native_adaptation.py`、`native_study.py` | 真实仓库的基线资格检查、适配、候选准入及冻结评测。 |
| `platform.py`、`training.py`、`command_experiment.py`、`bridge_runtime.py` | 独立训练调度、命令适配、测量回执与 Linux 沙箱。 |
| `followup.py`、`refutations.py` | 已测改进的组合与重训、数值边界探针、带适用协议的负向证据。 |
| `memory.py`、`replay.py`、`reproducibility.py` | 项目经验审批和可重建索引、实际测量复跑、版本冻结及归档控制器恢复。 |

控制阶段包括 `research`、`plan`、`execute`、`monitor`、`converge`、`curate` 与 `finalize`。发生分歧可进入 `review`，终态包括 `complete` 和 `stopped`。每次提交生成一个修订记录。任务租约持有控制进程身份，独立训练回执可用于重启后对账。

## 评测和信任边界

- 指标按冻结协议计算。多目标先排除不满足硬门槛的候选，再按目标方向和优先级排序。修改指标、划分或评价协议需要新基线。
- 原生隔离模式把训练、预测和评分放在分开的文件系统视图，限定可修改的源文件并保护标签与评分器。普通命令适配执行由项目提供的受信入口。Python 控制器也会调用外部模型服务与可访问的论文来源。
- 每个研究有独立项目 ID。候选经验有来源和适用条件，经自动筛查、独立逻辑审核与批准后才进入正式索引。正式索引按项目筛选。批准记录绑定内容哈希，发布目录按版本切换。
- 运行目录保留协议、候选代码、日志、测量、最终结论和版本信息。独立复跑比较一次既有测量，保留原始指标与复跑结果。Git 快照和锁定依赖帮助迁移，外部数据、原生库和训练解释器仍由实验方提供。
